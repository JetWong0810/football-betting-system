# 预测因子量化分析与优化建议

## 当前预测逻辑概览

当前项目的比赛预测核心在 `api-service/predict_service.py`，属于 6 因子亚盘方向预测：

| 因子 | 当前权重 | 当前来源 | 当前作用 |
| --- | ---: | --- | --- |
| 近期状态 | 1.5 | DeepSeek 分析近况文本 | 判断上盘/下盘基本面状态 |
| 交锋历史 | 1.0 | DeepSeek 分析交锋文本 | 判断双方历史对位优势 |
| 实力定位 | 2.0 | DeepSeek 分析排名和球队定位 | 判断盘口是否符合实力差 |
| 赔率变动 | 3.0 | 代码规则，基于 500.com 亚盘 | 根据上盘水位升降判断方向 |
| 市场热度 | 2.0 | DeepSeek 或用户手动描述 | 判断热门方向并逆向修正 |
| 单关修正 | 1.5 | 代码规则，基于市场热度 | 放大单关场次的热门逆向信号 |

当前逻辑可以作为规则型方向建议，但还不能作为可靠概率模型。主要原因是：

- 多个因子由 AI 直接给出方向和分数，可复现性和可回测性较弱。
- 综合计算里，`score` 没有充分参与方向强度，`6 分` 和 `10 分` 对方向贡献差异很小。
- 全因子中性时仍会默认输出下盘。
- F4 只取单家公司亚盘变化，未利用多公司一致性和盘口历史。
- F5 市场热度与 F6 单关修正存在重复计权。
- 缺少预测结果落库和历史比分数据，无法做命中率校准。

## 可量化且可获取实际数据的新增因子

以下因子可以基于当前项目已有数据源或小幅扩展获取实际数据，并转化为稳定的量化特征。

### 1. 欧赔隐含概率变化

数据来源：

- 500.com 欧赔数据。
- 当前项目已有 `fetch_european_odds(fid)`。

量化方式：

- 对初盘和即时盘分别计算去水后的主胜、平局、客胜隐含概率。
- 计算 `current_probability - initial_probability`。
- 如果上盘方对应的胜率概率持续上升，则支撑上盘。
- 如果上盘方胜率概率下降，或平局/下盘方概率明显上升，则削弱上盘。

示例特征：

| 特征 | 含义 |
| --- | --- |
| `euro_upper_prob_delta` | 上盘方欧赔隐含概率变化 |
| `euro_lower_prob_delta` | 下盘方欧赔隐含概率变化 |
| `euro_draw_prob_delta` | 平局概率变化 |
| `euro_mainstream_consensus` | 主流公司欧赔是否同向变化 |

价值：

- 判断胜平负市场预期是否支持亚盘方向。
- 可与亚盘变化形成交叉验证。

### 2. 亚盘多公司一致性

数据来源：

- 500.com 亚盘数据。
- 当前项目已有 `fetch_asian_handicap(fid)`。

量化方式：

- 选取主流公司：Pinnacle、Bet365、皇冠、澳门、威廉希尔、立博等。
- 对每家公司计算上盘水位变化。
- 统计上盘降水、上盘升水、升盘、降盘的公司比例。

示例特征：

| 特征 | 含义 |
| --- | --- |
| `asian_upper_water_drop_ratio` | 主流公司中上盘降水比例 |
| `asian_upper_water_rise_ratio` | 主流公司中上盘升水比例 |
| `asian_handicap_deepen_ratio` | 盘口加深比例 |
| `asian_handicap_shallow_ratio` | 盘口变浅比例 |
| `asian_consensus_score` | 多公司方向一致性得分 |

价值：

- 比当前只看单家公司更稳。
- 能降低单家公司异常报价或抓取误差带来的误判。

### 3. 亚盘离散度与市场分歧

数据来源：

- 500.com 亚盘数据。
- 当前项目已有 `fetch_asian_handicap(fid)`。

量化方式：

- 计算主流公司当前盘口标准差。
- 计算上盘水位标准差。
- 计算盘口方向分裂程度，例如一部分公司升盘、一部分公司降盘。

示例特征：

| 特征 | 含义 |
| --- | --- |
| `asian_handicap_std` | 当前盘口离散度 |
| `asian_upper_water_std` | 上盘水位离散度 |
| `asian_direction_conflict_ratio` | 主流公司方向冲突比例 |

价值：

- 不一定直接决定方向，但非常适合用于降低置信度。
- 市场分歧越大，置信度越应保守。

### 4. 大小球盘口变化

数据来源：

- 500.com 大小球数据。
- 当前项目已有 `fetch_over_under(fid)`。

量化方式：

- 计算大小球盘口从初盘到即时盘的升降。
- 计算大球/小球水位变化。
- 统计主流公司是否一致升盘或降盘。

示例特征：

| 特征 | 含义 |
| --- | --- |
| `ou_line_delta` | 大小球盘口变化 |
| `ou_over_water_delta` | 大球水位变化 |
| `ou_under_water_delta` | 小球水位变化 |
| `ou_consensus_score` | 大小球多公司一致性 |

价值：

- 辅助判断让球方是否具备穿盘空间。
- 强队让深盘时，如果大小球走低，可能提示大胜概率不足。

### 5. 近期战绩量化

数据来源：

- 500.com 基本面数据。
- 当前项目已有 `fetch_match_data(fid)`，其中包含 `homeRecent` 和 `awayRecent`。

量化方式：

- 近 5 场、近 10 场胜平负积分。
- 近 5 场、近 10 场净胜球。
- 主队主场近况、客队客场近况。
- 近期进球、失球、零封、被零封。

示例特征：

| 特征 | 含义 |
| --- | --- |
| `home_recent_points_5` | 主队近 5 场积分 |
| `away_recent_points_5` | 客队近 5 场积分 |
| `home_goal_diff_10` | 主队近 10 场净胜球 |
| `away_goal_diff_10` | 客队近 10 场净胜球 |
| `upper_recent_form_edge` | 上盘方近期状态优势 |

价值：

- 替代 AI 对近期状态的主观判断。
- 可以作为 F1 的核心量化输入。

### 6. 近期赢盘率

数据来源：

- 500.com 基本面数据。
- `fetch_match_data(fid)` 的近期战绩中已有 `asianResult`。

量化方式：

- 统计双方近 5 场、近 10 场赢盘、输盘、走水比例。
- 区分主客场赢盘率。
- 计算上盘方和下盘方的赢盘率差值。

示例特征：

| 特征 | 含义 |
| --- | --- |
| `upper_cover_rate_5` | 上盘方近 5 场赢盘率 |
| `lower_cover_rate_5` | 下盘方近 5 场赢盘率 |
| `upper_cover_rate_10` | 上盘方近 10 场赢盘率 |
| `cover_rate_edge` | 上下盘近期赢盘率差值 |

价值：

- 比单纯胜率更贴近亚盘方向预测。
- 是当前最值得新增的基本面量化因子之一。

### 7. 交锋赢盘率

数据来源：

- 500.com 基本面数据。
- `fetch_match_data(fid)` 的 `h2h` 中已有 `asianResult` 和盘口信息。

量化方式：

- 统计双方近 N 次交锋中，上盘方赢盘率。
- 统计类似盘口区间下的交锋赢盘率。
- 如果盘口差异过大，则降低交锋样本权重。

示例特征：

| 特征 | 含义 |
| --- | --- |
| `h2h_upper_cover_rate` | 交锋中上盘方赢盘率 |
| `h2h_sample_size` | 可用交锋样本数量 |
| `h2h_similar_handicap_cover_rate` | 类似盘口下交锋赢盘率 |

价值：

- 可以替代当前 F2 的主观判断。
- 但样本通常较小，权重不宜过高。

### 8. 赛程密度与体能

数据来源：

- 500.com 基本面数据。
- `fetch_match_data(fid)` 中包含近期战绩和未来赛程。

量化方式：

- 距上一场比赛天数。
- 距下一场比赛天数。
- 是否连续客场。
- 短周期内比赛数量。

示例特征：

| 特征 | 含义 |
| --- | --- |
| `home_rest_days` | 主队距离上一场比赛天数 |
| `away_rest_days` | 客队距离上一场比赛天数 |
| `rest_days_edge` | 上下盘休息天数差 |
| `next_match_days` | 距下一场比赛天数 |
| `fixture_congestion_score` | 赛程拥挤程度 |

价值：

- 能识别轮换和体能风险。
- 对杯赛、欧战前后、连续客场场景尤其有用。

### 9. 单关标记

数据来源：

- 本地竞彩数据。
- `matches.is_single` 和 `odds_win_draw_lose.is_single` 已有。

量化方式：

- 作为二元特征：`is_single = true/false`。
- 不建议作为独立强因子，建议用于修正市场热度或置信度。

价值：

- 单关场次通常关注度更高，热门方向更容易聚集。
- 但该信号和市场热度高度相关，不宜重复高权重计入。

### 10. 竞彩赔率隐含概率

数据来源：

- 本地 `odds_win_draw_lose`。
- 包含 HAD 和 HHAD 玩法赔率。

量化方式：

- 对胜平负、让球胜平负赔率分别计算去水隐含概率。
- 观察 HAD 与 HHAD 的概率结构是否一致。
- 用 HHAD 概率直接判断让球盘结果倾向。

示例特征：

| 特征 | 含义 |
| --- | --- |
| `had_home_prob` | 胜平负主胜去水概率 |
| `had_draw_prob` | 胜平负平局去水概率 |
| `had_away_prob` | 胜平负客胜去水概率 |
| `hhad_upper_prob` | 让球胜平负中上盘对应概率 |
| `hhad_lower_prob` | 让球胜平负中下盘对应概率 |

价值：

- 使用项目本地已有数据即可实现。
- 可作为 500.com 数据不可用时的兜底市场特征。

## 需要小幅扩展即可量化的因子

### 1. 临场盘口变化

数据来源：

- 当前已有 `fetch_asian_history(fid, cid)`，但预测流程中还没有批量使用。

量化方式：

- 拉取主流公司的亚盘历史。
- 分析开赛前 24 小时、6 小时、1 小时的盘口和水位变化。
- 对比早盘变化和临场变化是否一致。

价值：

- 临场数据通常比早盘更接近真实市场态度。
- 可识别早盘诱导和临场反向修正。

### 2. 欧赔历史变化

数据来源：

- 当前已有 `fetch_euro_history(fid, cid)`。

量化方式：

- 拉取主流公司欧赔历史。
- 计算主胜、平局、客胜去水概率在临场阶段的变化速度。

价值：

- 判断胜平负市场是否在临场阶段明显转向。

### 3. 大小球历史变化

数据来源：

- 当前已有 `fetch_ou_history(fid, cid)`。

量化方式：

- 拉取主流公司大小球历史。
- 计算临场盘口升降和大/小球水位变化。

价值：

- 辅助判断让球方穿盘空间。

### 4. 回测命中率

数据来源：

- 需要补充最终比分和预测记录落库。

建议新增数据：

- `match_results` 或在 `matches` 表补充 `home_score`、`away_score`。
- `prediction_records` 表保存每次预测的因子、特征、方向、置信度和时间。

价值：

- 只有可回测，置信度才可能从规则分数变成校准概率。

### 5. 联赛与盘口基准命中率

数据来源：

- 需要历史样本。

量化方式：

- 按联赛、盘口区间、主客让球、单关/非单关分桶。
- 统计上盘历史赢盘率、下盘历史赢盘率、走水率。

价值：

- 可作为模型的先验概率。
- 对小联赛和特殊盘口尤其有帮助。

## 不建议优先落地的因子

| 因子 | 原因 |
| --- | --- |
| 伤停阵容 | 数据源不稳定，通常需要外部 API 或人工维护 |
| 天气场地 | 对亚盘方向影响不如盘口、欧赔和赢盘率稳定 |
| 球队 ELO/xG | 价值高，但当前项目没有长期历史比赛数据库支撑 |
| 新闻舆情 | 噪声高，结构化困难，容易引入主观偏差 |

这些因子可以作为后续增强项，但不应优先于盘口、欧赔、赢盘率和回测校准。

## 推荐优先级

### P0：应优先改造

1. 亚盘多公司一致性。
2. 欧赔去水概率变化。
3. 近期赢盘率。
4. 全中性不再默认下盘。
5. 盘口方向归一，修正客队让球时的升降盘判断。

### P1：提升稳定性

1. 亚盘离散度与市场分歧。
2. 临场盘口变化。
3. 大小球盘口变化。
4. 竞彩 HHAD 去水概率。
5. 赛程密度与体能。

### P2：用于长期模型化

1. 预测记录落库。
2. 比赛最终比分落库。
3. 历史命中率回测。
4. 置信度校准。
5. 联赛和盘口分桶先验。

## 置信度优化建议

当前置信度更像规则分数，不应直接理解为真实命中概率。建议分两步优化。

### 短期方案

将置信度从百分比改为等级：

| 等级 | 条件示例 | 展示建议 |
| --- | --- | --- |
| 强信号 | 多数核心因子同向，市场分歧低 | 强信号 |
| 中等信号 | 核心因子同向但存在弱分歧 | 中等信号 |
| 弱信号 | 只有少数因子同向 | 弱信号 |
| 不建议 | 数据缺失、全中性、方向冲突严重 | 不建议 |

同时引入 `data_quality_score`：

- 数据缺失越多，置信度越低。
- 主流公司分歧越大，置信度越低。
- 盘口为空或平手盘方向不明确时，不输出强信号。

### 长期方案

建立预测回测和概率校准：

1. 保存每次预测的量化特征、因子得分、方向、置信度。
2. 保存最终比分并计算亚盘实际结果。
3. 用历史样本评估命中率、Brier Score、Log Loss。
4. 使用 Platt Scaling 或 Isotonic Regression 校准概率。
5. 输出 `calibrated_probability`，替代当前规则百分比。

## 建议的数据特征方向

最终可以将预测输入拆成三类：

### 基本面特征

- 近期积分差。
- 近期净胜球差。
- 近期赢盘率差。
- 交锋赢盘率。
- 休息天数差。
- 赛程拥挤程度。

### 市场特征

- 欧赔去水概率变化。
- HHAD 去水概率。
- 亚盘上盘水位变化。
- 亚盘盘口深度变化。
- 多公司一致性。
- 市场离散度。
- 临场变化速度。

### 风险特征

- 数据缺失比例。
- 主流公司方向冲突比例。
- 盘口异常变化。
- 单关标记。
- 热门方向集中度。

## 总体建议

当前预测框架可以保留，但建议逐步从“AI 主观打分 + 固定权重投票”转为：

1. 代码计算可复现的量化特征。
2. 规则或模型基于量化特征输出方向。
3. AI 只负责解释、摘要和补充非结构化信息。
4. 用历史回测校准置信度。

最先落地的因子应是：

- 亚盘多公司一致性。
- 欧赔去水概率变化。
- 近期赢盘率。
- 临场盘口变化。
- 数据质量和市场分歧。

这些因子数据可获取、实现成本低、和亚盘方向预测相关性更强，适合作为下一阶段优化重点。
