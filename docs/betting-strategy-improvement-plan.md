# 投注策略体系改造方案

## 一、目标

建立完整的"预测参考 → 策略推荐 → 投注执行 → 结算复盘"闭环，通过资金管理和风险控制实现长期盈利、尽量不亏本。

核心原则：
- 预测分析作为参考信号，不作为唯一决策依据
- 资金管理是核心（凯利公式 + 止损机制）
- UI体验优先，流程自然不割裂

---

## 二、现状问题

| 问题 | 描述 |
|------|------|
| 预测与投注脱节 | 预测完成后无后续动作，用户需要手动去记录页新建投注 |
| 策略页是独立计算器 | 需要手动输入胜率和赔率，不与实际投注流程关联 |
| 首页偏展示 | 展示统计数据但不提供决策指引 |
| 缺少投注建议 | 用户不知道该投多少钱，没有金额推荐 |
| 风险等级未使用 | configStore 有 riskTolerance 字段但无UI |
| 无复盘闭环 | 结算后没有和预测对比的分析 |

## 三、改造范围

### 3.1 预测页（predict.vue）— 增加投注建议卡片

预测完成后，在分析结果下方展示"投注建议"卡片：

```
┌─────────────────────────────────────────┐
│  投注建议                                │
├─────────────────────────────────────────┤
│                                         │
│  方向：上盘（置信度 72%）                  │
│  当前策略：稳健                           │
│  可用余额：¥8,420                        │
│                                         │
│  建议金额：¥250                          │
│  (Kelly ¥312 / 固定比例 ¥253 取较低值)    │
│                                         │
│  ┌─────────┐  ┌──────────────────┐     │
│  │ 调整金额 │  │  按此建议投注 →   │     │
│  └─────────┘  └──────────────────┘     │
│                                         │
│  ⚠ 提示：置信度<70%，建议减小投注比例      │
└─────────────────────────────────────────┘
```

**逻辑**：
- 用预测置信度作为胜率参考（仅参考，用户可调整）
- 结合当前风险策略计算推荐金额
- 置信度低于策略门槛时给出警告提示
- "按此建议投注"一键跳转记录页并预填信息

## 四、新增模块

### 4.1 策略引擎（utils/strategyEngine.js）

核心工具函数，被各页面共享调用：

```javascript
// 获取当前策略预设参数
getStrategyPreset(riskLevel) → { maxRatio, kellyFactor, stopLossLimit, maxDrawdown, minConfidence }

// 计算推荐投注金额
calcRecommendedStake({ bankroll, odds, confidence, riskLevel }) → { amount, kelly, fixed, method }

// 生成系统建议文字
generateAdvice({ consecutiveWins, consecutiveLosses, drawdown, riskLevel }) → { text, suggestedLevel, warning }

// 检查是否触发止损
checkRiskStatus({ consecutiveLosses, drawdown, riskLevel }) → { safe, reason, suggestedAction }
```

### 4.2 预测→投注桥接

预测页点击"按此建议投注"时，携带数据跳转：
- matchName, league, teams
- predicted_direction, confidence
- handicap, odds
- recommended_stake

跳转到记录页并自动打开投注对话框预填以上字段。

## 五、数据流变化

### 5.1 ConfigStore 扩展

新增字段（后端 user_config 同步）：
- `riskLevel`: 'conservative' | 'balanced' | 'aggressive' | 'custom'
- `minConfidence`: 最低置信度门槛（低于此值给警告）

### 5.2 BetStore 扩展

投注记录 bet_data 增加可选字段：
- `prediction_confidence`: 预测时的置信度
- `predicted_direction`: 预测方向
- `recommended_stake`: 系统建议金额（记录是否采纳）

### 5.3 StatStore 扩展

新增计算属性：
- `consecutiveWins`: 连胜场数
- `currentWeekStats`: 本周投入/盈亏/注数
- `predictionAccuracy`: 有关联预测的投注中，预测命中率

## 七、UI设计原则

- 保持现有设计语言：绿色主色(#0d9488)、小圆角(6rpx)、无emoji图标
- 投注建议用醒目但不打扰的方式呈现（卡片式，不是弹窗）
- 警告信息用柔和的黄色/红色背景提示，不用 alert
- 策略切换要有即时反馈（参数联动变化）
- 所有金额展示保持统一格式（¥ + 整数或两位小数）
