# 竞彩足球赛前基本面情报可行性与案例复盘

报告日期：2026-09-15

## 1. 结论摘要

可以通过“结构化足球数据 API + 官方俱乐部信息 + 新闻搜索 + LLM 结构化抽取”补齐阵容、伤停、赛程、轮换、战意和赛前新闻，但不能把“全网搜索”直接当作稳定数据源。

建议采用以下原则：

1. 近期战绩、积分、赛程、预计/确认阵容、球员伤停优先使用结构化 API。
2. 发布会、征召名单、轮换暗示、内部氛围等使用官方俱乐部和可靠本地媒体。
3. “战意”不是可直接抓取的事实，只能由排名目标、赛制、赛程和教练表态推断。
4. 新闻和伤停先作为“赛前情报修正层”展示，不应立即加入高权重投票。
5. 每条情报必须保存发布时间、抓取时间、原文来源和置信度，严格限制在开赛前。
6. 先验证增量预测价值，再决定是否进入正式因子。

本项目已有一部分基本面能力，并不是从零开始：

- 已抓取双方近期战绩、交锋和未来赛程。
- F1 已计算近期战绩、走势和主客场表现。
- 已有多公司亚盘、欧赔、竞彩赔率和临场变化。
- 日职模块已有阵容、天气、场地、球员赛季数据和来源优先级。
- 已有个人分析备注，可作为人工校验和灰度入口。

真正缺少的是一套面向所有联赛的统一赛前情报模型，以及赛前时间快照和质量控制。

## 3. 案例复盘：同赔并不是强主队信号

### 3.1 历史同赔的实际强度

该场项目保存的历史同赔结果为：

- 样本：11 场。
- 上盘：6 场，54%。
- 下盘：5 场，46%。
- 参考分：45。
- 因子方向：中性。

这不是足以支持主队的强信号，只能解释为“小样本中上盘略多”。11 场样本差一场就会明显改变比例，而且样本跨越英超、芬超、荷甲、欧战、意甲、瑞典超、日职、美职联等赛事，比赛环境并不相同。

历史同赔在此场的正确使用方式应是：

- 不单独下注。
- 不把 54% 显示成“主队概率高”。
- 当样本少、跨联赛、参考分低于阈值时，方向必须保持中性。
- 只作为赔率形态的弱先验，不能覆盖当前球队状态和临场市场变化。

### 3.2 完整预测实际上指向贝蒂斯

项目在开赛前 2 小时 24 分，即北京时间 2026-09-15 00:36 保存的完整预测为：

| 因子 | 方向 | 分数 | 主要依据 |
| --- | --- | ---: | --- |
| 近期状态 | 贝蒂斯/下盘 | 7 | 战绩、走势、客场表现均占优 |
| 实力定位 | 中性 | 5 | 双方底蕴接近 |
| 市场信号 | 贝蒂斯/下盘 | 8 | 亚盘和欧赔共同削弱主队 |
| 市场热度 | 贝蒂斯一侧偏热 | 7 | 多家公司主队升水 |
| 竞彩赔率 | 贝蒂斯/下盘 | 8 | 主胜升、客胜降 |
| 历史同赔 | 中性 | 5 | 6:5，无明确倾向 |
| 单关修正 | 贝蒂斯/下盘 | 8 | 单关叠加市场结构 |
| 交锋历史 | 贝蒂斯/下盘参考 | 5 | 按本场盘口重算后客队占优 |

最终预测：

- 方向：下盘，即比利亚雷亚尔不赢盘。
- 置信度：59%。
- 实际结果：皇家贝蒂斯 2-1 获胜，预测方向命中。

所以该案例暴露的首要问题不是“完整模型因为缺少基本面而判断错误”，而是：

1. 独立同赔页面容易让人把 54% 的弱差异理解为明确倾向。
2. 用户决策时可能没有充分看到完整模型与单项同赔的层级差异。
3. 现有“基本面”名称过窄，用户看不到阵容、伤停和新闻证据。
4. 当前预测虽然命中，但缺少可解释的赛前情报证据链。

## 4. 当时赛前公开信息能提供什么

### 4.1 近期状态

赛前公开信息和项目缓存均显示：

- 比利亚雷亚尔联赛开局不佳，赛前处于降级区附近。
- 比利亚雷亚尔最近三场正式比赛连续失利，包括联赛负于阿拉维斯、拉科鲁尼亚，以及欧冠负于多特蒙德。
- 皇家贝蒂斯赛前排名和积分明显更高。
- 贝蒂斯近期先后击败皇家社会、瓦伦西亚、皇家马德里，并在欧冠客场击败里尔。
- 项目 F1 已把双方近期状态量化为比利亚雷亚尔 40 分、贝蒂斯 69 分；最近五场趋势为 13 对 80。

这部分数据项目已经能够获取，并且赛前正确指向贝蒂斯。

### 4.2 赛程与体能

双方都在 2026-09-09 参加了欧冠客场比赛，到本场都有约五天恢复时间。

这意味着：

- 双方都存在欧战后的体能与轮换风险。
- 单纯以“贝蒂斯刚踢欧冠”为理由看衰客队不成立，因为主队面临同类问题。
- 应比较旅途、首发连续出场分钟、替补深度，而不是只统计休息天数。

现有 `homeFuture` 和 `awayFuture` 已抓到未来赛程，但还没有计算：

- 过去 14 天比赛数。
- 主力累计分钟。
- 连续客场次数和旅行距离。
- 下一场赛事重要性。
- 预计轮换人数。

### 4.3 伤停与阵容

赛前媒体信息显示：

- 比利亚雷亚尔的 Juan Foyth 缺阵。
- Carlos Romero 接近复出，最终进入首发。
- 贝蒂斯的 Aitor Ruibal 和 Diego Llorente 缺阵。
- 贝蒂斯仍能排出 Abde、Isco、Cucho Hernández 等主要进攻球员。
- Dani Ceballos 可以进入比赛名单，但最终从替补席开始。

这些信息的价值不在于简单统计“主队伤 1 人、客队伤 2 人”，而在于球员角色：

- 是否为稳定首发。
- 所在位置是否已有多人缺阵。
- 替代者能力差距。
- 是否影响阵型和出球方式。
- 是否刚伤愈、只能有限出场。

本场伤停数量本身没有形成压倒性方向，但“贝蒂斯核心攻击组可用、阵容深度足以轮换”降低了客队欧战后失速的风险。

### 4.4 教练、战意和球队氛围

赛前可观察到：

- 比利亚雷亚尔急需赛季首胜，教练面临结果压力。
- 贝蒂斯处于良好开局，目标是保持前列位置。
- 贝蒂斯由长期执教、体系稳定的 Pellegrini 带队。
- 比利亚雷亚尔虽然存在强烈抢分需求，但“急需赢球”同时意味着焦虑、压上和防守风险，不能自动等价为正向战意。

“战意”应拆成客观变量：

| 子项 | 可观测证据 |
| --- | --- |
| 积分目标 | 保级、争冠、欧战资格、晋级条件 |
| 容错空间 | 剩余轮次、与目标分差、净胜球 |
| 赛程优先级 | 联赛、杯赛、欧战下一场的重要性 |
| 轮换意图 | 教练发布会、征召名单、预计阵容 |
| 压力状态 | 连败、主场压力、教练帅位风险 |
| 奖励/纪律 | 奖金、停赛风险、累计黄牌 |

教练口号和“必须赢”只能作为低权重文本证据。

### 4.5 交锋和战术适配

赛前资料显示，比利亚雷亚尔此前连续四个主场对贝蒂斯未能取胜。项目的交锋模块也显示，按本场 -0.50 盘口重算后，贝蒂斯一侧的历史赢盘表现更好。

交锋数据不宜直接作为强因子，但可用于发现战术适配：

- 贝蒂斯能否利用主队压上后的空间。
- 主队后场缺员是否影响防守转换。
- 双方阵型是否形成边路或中场人数优势。

当前系统只有赛果和盘口层面的交锋，缺少阵型、球员和事件层面的战术特征。

### 4.6 市场已经提前反映风险

竞彩胜平负从初盘到临场：

| 结果 | 初盘 | 临场 | 变化 |
| --- | ---: | ---: | ---: |
| 主胜 | 1.77 | 1.88 | +0.11 |
| 平 | 3.65 | 3.62 | -0.03 |
| 客胜 | 3.45 | 3.12 | -0.33 |

去水后的隐含概率约从：

- 主胜 50.0% 降到 47.1%。
- 客胜 25.7% 升到 28.4%。

同时，多家公司维持主让半球但主队升水，Bet365 从主让半球退到平半。

这说明即使没有额外新闻源，临场市场本身已经持续修正到贝蒂斯一侧。新增基本面模块的主要价值是解释这次修正是否有事实支持，而不是重复计算同一个市场信号。

## 5. 全网数据获取的可行性

### 5.1 可稳定结构化获取

| 数据 | 可行性 | 建议来源 | 更新时点 |
| --- | --- | --- | --- |
| 赛程、积分、排名 | 高 | 足球数据 API、官方联赛 | 每日/T-24h |
| 近期比赛和统计 | 高 | 足球数据 API | 赛后 |
| 伤停名单 | 中高 | API-Football、Sportmonks 等 | T-48h 至 T-1h |
| 停赛 | 高 | API、官方纪律公告 | T-48h |
| 预计阵容 | 中 | 数据商、可靠本地媒体 | T-24h/T-6h |
| 确认首发 | 高 | 联赛、数据商、俱乐部官方 | T-75m 至 T-45m |
| 球员赛季出场/进球 | 高 | 足球数据 API | 每日 |
| 天气 | 高 | Open-Meteo 等 | T-24h/T-3h |
| 赛程密度 | 高 | 本地由赛程计算 | 每次预测 |

API-Football 当前公开能力包含 fixtures、standings、lineups、players、sidelined、injuries、statistics 和 predictions，适合低成本试点。Sportmonks 的 fixture includes 更丰富，包含 lineups、sidelined、prematchNews、weatherReport、expectedLineups、predictedLineups 和 xG 等，适合后续扩展。

### 5.2 需要搜索和文本抽取

| 数据 | 可行性 | 主要来源 | 主要风险 |
| --- | --- | --- | --- |
| 教练发布会 | 中高 | 俱乐部官网、官方视频、本地媒体 | 视频无文字稿 |
| 征召名单 | 高 | 俱乐部官方 | 发布时间较晚 |
| 轮换暗示 | 中 | 发布会、跟队记者 | 表述模糊或烟雾弹 |
| 更衣室氛围 | 低中 | 多家可靠媒体交叉确认 | 谣言多 |
| 战意描述 | 中 | 排名/赛制计算 + 发布会 | 主观解释 |
| 战术变化 | 中 | 预计阵容、记者分析 | 难标准化 |

搜索层建议使用搜索 API，而不是直接抓取搜索引擎结果页。候选方案：

- Brave Search API：获取网页和新闻候选。
- NewsAPI：按球队、球员、教练和时间窗口搜索新闻。
- GDELT：用于多语言新闻补充。
- 俱乐部官网、联赛官网和官方社交账号白名单。

### 5.3 无法稳定“获取”的内容

以下内容不能被当作确定事实：

- 球员真实心理状态。
- 教练未公开的轮换计划。
- 更衣室内部矛盾。
- 球队“必胜决心”的真实强度。
- 未确认的轻伤是否影响首发。

系统只能保存证据并给出推断置信度，不能伪装成确定数据。

## 7. 抓取时点

建议每场建立不可变快照：

| 时点 | 主要任务 |
| --- | --- |
| T-48h | 初始伤停、停赛、赛程、积分目标、官方新闻 |
| T-24h | 发布会、征召名单、预计阵容、天气 |
| T-6h | 伤停更新、跟队记者信息、市场变化交叉验证 |
| T-75m | 确认首发、替补名单、阵型 |
| T-15m | 临场阵容异常、热身伤退、最终市场变化 |

预测记录必须引用具体 `snapshot_id`。赛后复盘只能读取当时快照，不能读取后来更新过的伤停状态或新闻摘要。

## 8. 来源优先级和冲突处理

来源等级：

1. 联赛、俱乐部、足协官方公告。
2. 有稳定数据质量的结构化提供商。
3. 俱乐部跟队记者和可靠本地媒体。
4. 全国性体育媒体。
5. 聚合站、预测站和社交媒体。

冲突规则：

- 官方确认覆盖所有非官方消息。
- 两个独立可靠来源可把 doubtful 提升为 probable。
- 单一匿名消息只能标记 rumor，不参与分数。
- 旧消息不能覆盖新消息。
- 球员已进入确认首发后，之前的 doubtful 自动关闭。
- 同一消息被多家转载不能算多个独立来源。

## 9. 因子设计建议

不建议直接新增四个独立高权重因子，否则伤停、阵容、轮换、新闻会高度相关并被重复计票。

建议新增一个“赛前情报修正”：

| 子项 | 初始权重 | 说明 |
| --- | ---: | --- |
| 核心球员可用性 | 0.40 | 伤停、停赛、伤愈限制 |
| 确认阵容强度 | 0.30 | 只在首发公布后提高权重 |
| 赛程与轮换 | 0.15 | 休息、连续客场、主力分钟 |
| 战意与赛事优先级 | 0.10 | 客观积分目标为主 |
| 可靠新闻异常 | 0.05 | 教练更换、内部事件等 |

整体修正上限建议等价于现有 1.0 至 1.5 个因子，避免新闻覆盖盘口和长期数据。

初期仅输出三种结果：

- `support_upper`
- `support_lower`
- `risk_or_no_bet`

确认首发公布前，不允许新闻情报产生“强信号”。当来源冲突或关键位置不确定时，应优先降低置信度，而不是强行选边。

## 11. 分阶段落地方案

### 阶段 A：两周试点，只展示不加权

范围：

- 西甲、英超、意甲、德甲、法甲。
- 接入一个结构化 API。
- 接入俱乐部官网和一个搜索 API。
- 展示伤停、预计阵容、赛程密度、官方新闻和来源时间。
- 支持人工纠错。

目标：

- 验证比赛映射和球员映射。
- 统计覆盖率、延迟和冲突率。
- 防止赛后信息污染。

### 阶段 B：历史快照与离线评分

至少积累 300 至 500 场有完整赛前快照的比赛。

评估：

- 单独情报方向命中率。
- 加入情报前后的 Brier Score 和 Log Loss。
- 对不同联赛、盘口和时间点分桶。
- 在赔率已经明显变化时，情报是否仍提供增量价值。

### 阶段 C：小权重上线

只有满足以下条件才进入正式预测：

- 主要联赛覆盖率大于 85%。
- 确认阵容在开赛前 45 分钟覆盖率大于 95%。
- 伤停冲突率可控。
- 离线回测对概率校准有稳定提升。
- 不同时间区间回测结果一致，不只在单一月份有效。

### 阶段 D：自动校准

由历史结果学习：

- 球员缺阵影响。
- 替补深度。
- 阵容变化对不同盘口的影响。
- 各来源真实可靠度。
- 情报发布时间距离开赛的有效性。

## 12. 推荐选型

短期最低成本方案：

1. API-Football 试用：获取伤停、停赛、预计/确认阵容、积分和球员信息。
2. Brave Search API 或 NewsAPI：检索赛前发布会和官方新闻。
3. 俱乐部官网白名单：作为最高等级文本来源。
4. DeepSeek/OpenAI：只做实体抽取、去重、证据摘要和冲突判断。
5. 保留人工修正入口。

需要更丰富单一数据源时，可评估 Sportmonks，其 fixture 关联数据覆盖阵容、缺阵、赛前新闻、天气、预计阵容和 xG，但必须先用目标联赛实测覆盖率和发布时间。

不建议：

- 把搜索结果摘要直接作为事实。
- 依赖单个免费比分站的非公开接口。
- 把 Transfermarkt 等网页抓取作为生产主数据源。
- 让 LLM 凭球队名称自行生成伤停和战意。
- 未做历史快照就直接回测新闻因子。

## 13. 对本场比赛的最终判断

如果在赛前完整使用现有数据和可获取情报，合理结论应为：

- 历史同赔：中性，不能支持主队单独下注。
- 近期状态：明显支持贝蒂斯。
- 排名与开局：支持贝蒂斯。
- 赛程体能：双方接近。
- 伤停阵容：没有形成主队优势，贝蒂斯主要攻击组可用。
- 战意：主队抢首胜意愿强，但压力和防守风险并存，不能作为主队利好。
- 交锋适配：偏贝蒂斯。
- 亚欧盘变化：明确削弱主队。

推荐决策层级：

1. 首选“贝蒂斯受让/下盘”。
2. 若只做胜平负，可考虑“贝蒂斯不败”而不是直接要求客胜。
3. 若临场确认贝蒂斯主要攻击手缺阵，再降级为观望。
4. 不应因为同赔 6:5 就选择主队。

本场说明基本面情报值得补充，但更直接的产品改进是：把低质量同赔明确标记为“中性/弱样本”，并在页面上突出“单项参考不等于综合预测”。
